# Instruction Memory

Instruction memory is a critical component of the **Star Virtual Machine**. It stores the machine code generated by the assembler, which is executed by the virtual machine during runtime. Instruction memory is organized as a dynamic array of bytes, where each instruction is represented by two bytes (16 bits). This allows for efficient access and execution of instructions.

You can read more about how instructions are generated in the [generation stage documentation](/docs/generation-stage.md).

## Why a Dynamic Array?

Instruction memory is implemented as a dynamic array to allow for flexible resizing. This is necessary because the size of the program is not known at assembly time. The dynamic array can grow as needed, accommodating larger programs without requiring a fixed size.

## Program Counter

The program counter (PC) is a special register that keeps track of the current instruction being executed. It points to the address of the next instruction in instruction memory. The PC is automatically incremented after each instruction execution, allowing the virtual machine to execute instructions sequentially.

The PC can also be modified by control flow instructions, such as jumps and branches, which change the flow of execution based on conditions or labels defined in the code.

To fetch the current instruction, the PC is multiplied by 2, as each instruction occupies two bytes in instruction memory. This means that the PC value is always even, and it points to the start of a valid instruction.

You can read more about how the PC is used in the [execution stage documentation](/docs/execution-stage.md).

## Example of Instruction Memory Usage

```python
.instr
    add $zero, $zero, $zero
```
The code above produces the following instruction memory layout:

| Address |   Value    |
|:-------:|:----------:|
| 0x0000  | 0b00000000 |
| 0x0001  | 0b00000000 |
