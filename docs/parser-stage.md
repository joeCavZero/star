# Parser Stage

The parser stage is responsible for analyzing the token stream produced by the scanner and constructing a structured representation of the source code, typically in the form of an abstract syntax tree (AST). This stage checks the syntax of the code and ensures that it adheres to the rules defined by the language grammar.

## How the Parser Works

The parser reads the token stream generated by the scanner and applies a set of grammar rules to identify valid constructs in the source code. It builds an abstract syntax tree (AST) that represents the hierarchical structure of the code, capturing relationships between different elements such as instructions, labels, and directives.

The parser also performs semantic analysis, checking for errors such as undefined labels, incorrect instruction usage, and type mismatches. If any errors are found, the parser generates error messages that indicate the nature of the problem and its location in the source code.

You can read more about how the AST is processed in the [resolver stage documentation](/docs/resolver-stage.md).

## Example of Parser Output
```python
.data
    string: .stringz "Hello World!"
.instr
    la $g, string
```
The parser would produce an AST like:

```
    - data-section:
        - data-section-item:
            - label-definitions: [
                "string"
            ]
            - directive: ".stringz"
            - string-literal: "Hello World!"
    - instruction-section:
        - instruction-section-item:
            - directive: ".instr"
            - instruction: "la"
            - sequence:
                - register: "$g"
                - identifier: "string"
```

The abstract syntax tree (AST) in the **Star Virtual Machine** is structured in two main sections: the data section and the instruction section. Each section contains items that can handle label definitions, directives, instructions, and arguments.

Usually, ASTs are represented as a tree structure, but in the **Star Virtual Machine**, the AST is represented as a list of items. Each item can be a data section item or an instruction section item, allowing for a more flexible and linear representation of the code structure.

You can read more about how the AST is used to generate code in the [generation stage documentation](/docs/generation-stage.md).
